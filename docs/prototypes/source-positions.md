# Prototype: source positions of rendered blocks

Issue #7. Question: the reading view moves a block cursor with `j` / `k`, and
the edit key opens the source with the cursor on that block. Typst's HTML
export carries no source positions: how can a rendered block be traced back
to its source?

**Answer: with the spans the compiler already keeps.** No order matching and
no attributes injected from Typst code are needed.

## How it works

1. **Source blocks** (`crates/musubi-typst/src/blocks.rs`): the note is
   parsed with `typst-syntax` and its top-level syntax nodes are grouped into
   blocks: headings, paragraphs (inline runs between blank lines), list,
   enumeration and term items, display equations, code blocks, and calls (a
   code expression alone, such as `#card[…]`). Each block has its byte range
   and its lines.
2. **Rendered elements** (`source_map.rs`): before encoding the HTML, the
   compiler's tree is walked. Every element and text node keeps the span of
   the syntax that produced it. An element whose spans in the note all fall in
   one block gets `data-block="<index>"`. An element that covers several
   blocks (a `<ul>` holds one item per block) is skipped and its children are
   examined.
3. **Reading view**: `j` / `k` move between the blocks present in the page,
   a click selects the block under the pointer, and the demo page prints the
   kind, lines and bytes of the selected block.

```html
<h2 data-block="1">Blocks</h2>
<ul>
	<li data-block="3">
		First item
		<ul>
			<li>Nested item</li>
		</ul>
	</li>
	<li data-block="4">Second item</li>
</ul>
<div class="musubi-card" data-block="8">…</div>
```

Cost: one walk over the tree per compilation, negligible next to the
compilation itself.

## Edge cases

| Case                                                  | Behaviour                                                                                                                                                                                                                                                                    |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Nested list items                                     | Belong to their top-level item: the cursor moves by top-level item. Finer moves can come later if the need appears.                                                                                                                                                          |
| `#import`, `#set`, `#let`, `#show` alone              | Blocks of kind `call` that render nothing: the cursor skips them, since it only visits blocks present in the page.                                                                                                                                                           |
| Functions of the `musubi` package (`card`)            | The wrapper element comes from the package, but its text comes from the note: the card maps to its call.                                                                                                                                                                     |
| Variable defined in one block, used in another        | The text of `#greeting` has the span of its definition. When an element mixes several blocks and has no child element, it goes to the last one, which is the use in the usual order "define, then use".                                                                      |
| Content generated by a function (`#lorem(10)`, loops) | The generated text has the span of the call: it maps to the call's block.                                                                                                                                                                                                    |
| `show` rules that wrap content in new elements        | The new elements have the span of the rule, so they cover two blocks; the innermost element made only of the content gets the content's block (`<p><strong data-block="4">` for a restyled heading). A rule that replaces the content with fixed text leaves nothing to map. |
| Content from another file (`#include`)                | Spans outside the main note are ignored: the included content is not selectable. Musubi notes rarely include others.                                                                                                                                                         |

## Limits

- Byte ranges are UTF-8 offsets; the interface works in lines, and the editor
  will convert to its own positions (CodeMirror uses UTF-16 offsets).
- The block list comes from the syntax tree, so a block that a `show` rule
  hides is still in the list; the cursor ignores it because it is not in the
  page.
